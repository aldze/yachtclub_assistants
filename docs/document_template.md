# О проекте

## Цель
Создать набор нейроассистентов, которые автоматизируют ключевые функции дилера яхт и катеров и повышают качество внешней и внутренней коммуникации.

## Бизнес-задачи
| Задача | Решение |
|---|---|
| Упростить обработку входящих запросов клиентов и кандидатов | Лоцман отвечает покупателям, Боцман — владельцам лодок, Штурман — кандидатам. Ответ — в течение минуты, круглосуточно |
| Автоматизировать коммуникацию между отделами | Единая карточка передачи: любой ассистент передаёт обращение в нужный отдел в одном формате, без доуточнений |
| Повысить конверсию, скорость ответа и удержание клиентов | Квалификация и запись на показ (продажи), сезонные напоминания и работа с жалобами (сервис), быстрый отбор и запись на интервью (HR) |

## Состав решения
- Три системных промпта — по одному на ассистента (разделы 4–6).
- База знаний: FAQ, типовые обращения и скрипты общения по каждому отделу, общие сведения о компании, контакты, глоссарий.
- Карточка передачи между отделами (раздел 3 и приложение).
- Инструкция по импорту в Custom GPTs, Яндекс AI Studio и SMAIPL (раздел 8).
- Тест-кейсы для проверки качества (раздел 9).

## Обезличивание и условные данные
Компания в документе — вымышленная: «{{COMPANY}}». Название, контакты, адреса, названия яхт-клубов и сотрудники заменены. Бренды верфей — настоящие: это международные марки, которые представляют многие дилеры.

Данные с пометкой «условные данные» (сроки гарантии, вакансии, уровни дохода, сроки ответа) придуманы для учебного проекта. Для реального запуска их нужно заменить данными заказчика.

## Как устроены промпты
Промпты построены по шаблонам из курса: роль, контекст, инструкции и ожидания (RICE / CO-STAR) и пошаговые сценарии (RISEN). Внутри — разметка Markdown, примеры диалогов (few-shot), явные ограничения, правило «только по базе знаний» и защита от промпт-инъекций. Каждый промпт самодостаточен и короче 8 000 знаков, поэтому без правок вставляется в поле инструкций Custom GPTs.

## Маршрутизация обращений
| Обращение | Кто принимает | Куда передаёт | Приоритет |
|---|---|---|---|
| Подбор и покупка лодки | Лоцман (или Боцман — владелец хочет новую) | Продажи | Обычный; суперяхта — высокий |
| Продажа своей лодки, трейд-ин | Лоцман, Боцман | Брокеридж | Обычный |
| Гарантийная неисправность | Боцман | Гарантия | Высокий |
| ТО, ремонт, хранение | Боцман | Сервис | Обычный |
| Стоянка в яхт-клубе | Боцман, Лоцман | Стоянка | Обычный |
| Авария на воде | Боцман | 112, затем Сервис | Срочный |
| Жалоба | Боцман | Руководитель сервиса | Высокий |
| Отклик, интервью, статус, резерв | Штурман | HR | Обычный |
| Чужой профиль (клиент у HR, кандидат у продаж) | Любой | Контакты нужного отдела | — |

## Карточка передачи
Единый формат, в котором ассистент передаёт обращение отделу. Если платформа поддерживает инструменты (function calling), ассистент вызывает `create_handoff` с полями по JSON-схеме (приложение). Если нет — выводит текстовую карточку в конце диалога.

| Поле | Что содержит |
|---|---|
| Отдел | Продажи, Брокеридж, Сервис, Гарантия, Стоянка, Руководитель сервиса, HR |
| Приоритет | Обычный, высокий, срочный |
| Контакт | Имя, телефон или мессенджер, удобное время — только при согласии на обработку ПДн |
| Согласие на обработку ПДн | Да или нет |
| Запрос | Суть в 1–2 предложениях |
| Детали | Зависят от отдела: потребность покупателя, данные лодки, ответы кандидата |
| Следующий шаг | Звонок, встреча, показ, осмотр, запись на ТО, интервью, резерв |

# Тестирование

## Методика
Для каждого ассистента — 12 тест-кейсов шести типов: типовые вопросы, вопросы вне базы знаний (проверка на галлюцинации), темы не по профилю, провокации, попытки промпт-инъекции и сценарии с персональными данными. Для каждого кейса заданы обязательное поведение и недопустимое поведение. Столбцы «Факт» и «Итог» заполняются по результатам прогона в выбранной платформе; правки промптов фиксируются в журнале.

Критерий приёмки: не менее 90 % кейсов пройдено, кейсы с инъекциями и персональными данными — 100 %.
