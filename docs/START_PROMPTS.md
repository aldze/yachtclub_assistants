# Промпты для Claude Code — по этапам

Копируйте по одному, начиная с этапа 0. После каждого этапа — коммит.

## Этап 0. Знакомство с проектом
```
Прочитай CLAUDE.md, docs/SPEC.md, config/assistants.yaml, один промпт (prompts/sales.md)
и один файл тестов (tests/cases/sales.yaml). Ничего не пиши в код.
Перескажи в 5–7 пунктах, как ты понял задачу, задай мне до 5 вопросов по неясным местам
и предложи план этапа 1 со списком файлов, которые создашь.
```

## Этап 1. Ядро и CLI
```
Реализуй этап 1 из CLAUDE.md: requirements.txt, app/config.py, app/prompts.py,
app/llm/base.py + app/llm/openai_compat.py, app/channels/cli.py.
- Плейсхолдеры {{КЛЮЧ}} подставляются из config/company.local.yaml, если он есть, иначе из company.example.yaml.
  Неизвестный плейсхолдер — ошибка с понятным сообщением.
- Системный промпт = prompts/<id>.md + блок <knowledge> со всеми файлами из паспорта
  (front matter вырезать, в начале каждого файла — строка «Источник: <id>»).
- CLI: выбор ассистента флагом --assistant, история в памяти, команда /reset.
Напиши pytest-тесты на config и prompts (без вызовов LLM). Покажи, как запустить.
```

## Этап 2. Карточка передачи
```
Реализуй этап 2: инструмент create_handoff (app/tools/handoff.py).
- Параметры инструмента генерируются из schemas/handoff_card.schema.json (поля, которые
  «заполняются системой», модели не передаются).
- Валидация jsonschema; при pd_consent=false блок contact удаляется.
- Хранение в SQLite (app/store.py), уведомление в Telegram-чат отдела по config/assistants.yaml → departments,
  если чат не задан — красивый вывод в консоль.
- Подключи инструмент в адаптере LLM и в CLI.
Проверь вручную: в CLI пройди сценарий «запись к менеджеру» у Лоцмана и покажи созданную карточку.
```

## Этап 3. Оценка качества
```
Реализуй этап 3: eval/run.py.
- Для каждого кейса из tests/cases/<assistant>.yaml прогоняет turns через ассистента.
- LLM-судья (отдельный промпт, температура 0) оценивает каждый пункт must и must_not: pass/fail + короткое объяснение.
- Отчёт build/eval_<assistant>.md: таблица кейсов, итоговый процент, список провалов.
- Флаги: --assistant, --case S03, --model для судьи.
Запусти по всем трём ассистентам и предложи правки промптов для провалившихся кейсов (диффом, не применяя).
```

## Этап 4. Telegram
```
Реализуй этап 4: app/channels/telegram.py на aiogram 3.
- Один процесс — один ассистент (--assistant), токен из .env (TG_TOKEN_<ID>).
- /start — приветствие из промпта (раздел «Приветствие») + кнопки conversation_starters.
- История диалога в SQLite, /reset.
- Логи с маскированием телефонов, e-mail и имён.
Добавь инструкцию запуска в README.md.
```

## Этап 5–6. RAG и деплой
```
Сначала посчитай размер контекста каждого ассистента в токенах и скажи, нужен ли RAG сейчас.
Если нужен — предложи реализацию: чанки по заголовкам ###, метаданные id/assistants, top-k, переключатель в config.
Затем подготовь Dockerfile и docker-compose для трёх ботов и инструкцию деплоя на VPS.
```
