# Публичный запуск на сервере

Инструкция для этапа 6: как выложить единое окно (сайт с виджетом и Telegram-бот) на свой сервер, чтобы им мог пользоваться любой посетитель. Команды можно повторять по порядку.

## 1. Что получится

```
посетитель ──HTTPS──▶ caddy ──▶ web (виджет и API) ──▶ OpenAI
                       │            │
            сертификат Let's Encrypt  └── data/: SQLite (диалоги, карточки), кеш эмбеддингов
Telegram ◀──────────── telegram (бот единого окна, по желанию)
```

Все работает в Docker: три контейнера описаны в `docker-compose.yml`.
- **web** — наше приложение (`python -m app.channels.web`).
- **caddy** — веб-сервер перед ним. Сам получает и продлевает HTTPS-сертификат, наружу открыты только порты 80 и 443.
- **telegram** — бот. Включается отдельно, если нужен.

**Почему Docker.** На сервере не нужно ставить Python и зависимости. Образ собирается одинаково везде, и то, что работает у вас на компьютере (`docker compose up`), так же заработает на сервере.

## 2. Что нужно заранее

1. **Сервер (VPS)**: 1 ядро, 1–2 ГБ памяти, Ubuntu 24.04 — самый дешевый тариф подойдет.
   **Важно про расположение.** OpenAI не принимает запросы из России. Для учебного запуска на OpenAI берите сервер за рубежом (например, в Европе) или задайте в `OPENAI_BASE_URL` шлюз, совместимый с OpenAI.
   Для реального запуска с ПДн российских клиентов нужно наоборот: сервер в России, а модель — YandexGPT или GigaChat (152-ФЗ, CLAUDE.md, решение 3).
2. **Домен** или поддомен, например `chat.example.ru`. В панели регистратора создайте A-запись: `chat` → IP сервера. Сертификат выдается только на домен, на голый IP — нет.
3. **Ключ OpenAI с лимитом расходов.** Сайт открыт всем, поэтому в кабинете OpenAI (Settings → Limits) поставьте месячный лимит. Это вторая страховка после лимитов в коде (раздел 6).

## 3. Подготовка сервера

Подключитесь по SSH (IP и пароль или ключ дает хостинг):

```bash
ssh root@<IP сервера>
```

Поставьте Docker и откройте только нужные порты:

```bash
curl -fsSL https://get.docker.com | sh       # официальный установщик Docker с compose
ufw allow OpenSSH && ufw allow 80 && ufw allow 443 && ufw --force enable
```

## 4. Код на сервере

Проще всего — через приватный репозиторий GitHub (как выложить проект — `docs/GIT_TUTORIAL.md`):

```bash
git clone https://github.com/<логин>/yachtclub_assistants.git
cd yachtclub_assistants
```

Для приватного репозитория GitHub спросит логин и токен (Settings → Developer settings → Personal access tokens).

Без GitHub код можно скопировать с компьютера, из папки проекта:

```bash
rsync -av --exclude .venv --exclude .git --exclude data --exclude build --exclude '*.local.*' \
      ./ root@<IP сервера>:yachtclub_assistants/
```

Реальные данные компании (`config/company.local.yaml`) и слова-маркеры на сервер **не копируются**: в Docker-образ они не попадают (`.dockerignore`). Публичная версия работает на легенде из `config/company.example.yaml`.

## 5. Настройки (.env)

```bash
cp .env.example .env
nano .env
```

Обязательно:

| Переменная | Что вписать |
|---|---|
| `OPENAI_API_KEY` | ключ OpenAI |
| `DOMAIN` | ваш домен, например `chat.example.ru` |

По желанию:

| Переменная | Зачем |
|---|---|
| `WEB_ALLOWED_ORIGINS` | если виджет встраивается на другой сайт: `https://example.ru` |
| `WEB_RATE_LIMIT`, `WEB_DAILY_LIMIT` | лимиты запросов (раздел 6) |
| `TG_NOTIFY_TOKEN`, `TG_ALERT_CHAT` | оповещения об ошибках в Telegram (раздел 8) |
| `TG_TOKEN_WINDOW` | токен бота от @BotFather, если нужен Telegram |
| `TG_CHAT_SALES` и другие | чаты отделов для карточек передачи |

Комментарии к пустым значениям пишите отдельной строкой. Docker compose читает `KEY=   # текст` как значение «# текст». Код такие значения считает пустыми, но лучше не путать.

## 6. Защита публичного сервиса

Каждая реплика посетителя — платный запрос к модели, а адрес сайта знают все. Поэтому в `app/limits.py` два лимита:

- **на посетителя**: `WEB_RATE_LIMIT=30/600` — не больше 30 запросов с одного IP за 10 минут;
- **на весь сервис**: `WEB_DAILY_LIMIT=1500` — не больше 1500 реплик в сутки.

При превышении посетитель видит текст из `config/assistants.yaml` → `window.limit_text`. Ответ модели при этом не запрашивается.

Еще ограничения:
- реплика — не длиннее 2000 знаков;
- тело запроса — не больше 64 КБ;
- контейнер работает не от root;
- база доступна только внутри Docker;
- в логах телефоны и e-mail замаскированы, а текст реплик не пишется вообще.

## 7. Запуск

```bash
docker compose up -d --build                     # сборка образа и запуск web + caddy
docker compose ps                                # web — healthy, caddy — running
curl https://<домен>/health                      # {"ok": true}
```

Откройте `https://<домен>/`: на демо-странице справа внизу будет чат-виджет.

На первом запуске Caddy получает сертификат. Для этого домен уже должен указывать на сервер, а порты 80 и 443 — быть открыты. Если сертификат не выдается, смотрите `docker compose logs caddy`.

Telegram-бот (нужен `TG_TOKEN_WINDOW`):

```bash
docker compose --profile telegram up -d
```

Встраивание виджета на настоящий сайт — одна строка перед `</body>`:

```html
<script src="https://<домен>/static/widget.js" data-api="https://<домен>" defer></script>
```

Адрес сайта добавьте в `WEB_ALLOWED_ORIGINS` и перезапустите: `docker compose up -d`.

## 8. Мониторинг ошибок

- **Проверка живости.** Docker каждые 30 секунд спрашивает `/health` и перезапускает упавший контейнер (`restart: unless-stopped`).
  Снаружи можно подключить бесплатный UptimeRobot или аналог: он раз в 5 минут проверяет `https://<домен>/health` и пишет на почту, если сервер не отвечает.
- **Ошибки в Telegram.** Создайте бота у @BotFather (или возьмите тот же, что для карточек) и добавьте его в чат для оповещений.
  Узнать id чата: напишите в чат что-нибудь и откройте `https://api.telegram.org/bot<токен>/getUpdates`.
  Впишите `TG_NOTIFY_TOKEN` и `TG_ALERT_CHAT` в `.env` и перезапустите.
  Каждая ошибка уровня ERROR придет сообщением, например «модель недоступна» или «закончился баланс». Одинаковые ошибки — не чаще раза в 10 минут. Телефоны и e-mail в оповещениях замаскированы.
- **Логи.**

  ```bash
  docker compose logs -f web           # журнал приложения в реальном времени
  docker compose logs --since 1h web   # за последний час
  ```

## 9. Обновление и откат

После правок на компьютере закоммитьте и отправьте изменения на GitHub (`git push`). Затем на сервере:

```bash
cd yachtclub_assistants
git pull
docker compose up -d --build         # пересобирает образ, база и сертификаты сохраняются в томах
```

Откат на прошлую версию: `git log --oneline` → `git checkout <коммит>` → `docker compose up -d --build`.

## 10. Резервная копия базы

Диалоги и карточки лежат в томе `data` (SQLite). Копия, которую можно делать на работающем сервисе:

```bash
docker compose exec web python -c "import sqlite3; sqlite3.connect('/app/data/app.sqlite3').backup(sqlite3.connect('/app/data/backup.sqlite3'))"
docker compose cp web:/app/data/backup.sqlite3 ./backup-$(date +%F).sqlite3
```

Файл копии содержит ПДн посетителей. Храните его так же аккуратно, как сам сервер.

## 11. Перед реальным запуском (не для учебного)

Учебная публичная версия работает на легенде и OpenAI. Для настоящего заказчика нужно еще:

1. **152-ФЗ.** Сервер в России, модель YandexGPT или GigaChat (адаптеры `app/llm/yandex.py`, `gigachat.py` еще не написаны). На сайте — политика обработки ПДн, ссылка на нее рядом с виджетом.
2. **Срок хранения диалогов.** Сейчас история хранится бессрочно. Нужна регулярная очистка старых сессий.
3. **Модели сильнее** и приемочный прогон `python -m eval.run --repeat 3 --model gpt-4.1` (CLAUDE.md).
4. **Реальные данные компании.** Через `config/company.local.yaml`, подключенный к контейнеру томом. Это сознательное решение заказчика.

## 12. Проверка на своем компьютере

Перед сервером ту же связку можно поднять локально. Нужен Docker Desktop.

```bash
docker compose up -d --build          # DOMAIN не задан — сайт на https://localhost
curl -k https://localhost/health      # -k: локальный сертификат самоподписанный
docker compose down                   # остановить (данные в томах сохранятся)
```
