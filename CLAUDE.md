# CLAUDE.md — Нейроассистенты для компании по продаже яхт

Этот файл читается Claude Code в начале каждой сессии. Здесь собраны контекст проекта, правила и план работ.

## Что это за проект
Три LLM-ассистента для дилера моторных яхт и катеров:
- **Лоцман** (`sales`) — консультант отдела продаж: выявляет потребность, предлагает лодки, передаёт тёплый запрос менеджеру;
- **Боцман** (`service`) — сервис и постпродажа: гарантия, ТО, хранение, стоянка, жалобы;
- **Штурман** (`hr`) — HR: вакансии, предварительный отбор, запись на интервью.

Связь между отделами — через единую **карточку передачи** (`schemas/handoff_card.schema.json`), которую любой ассистент отправляет в нужный отдел.

Это учебный проект курса «Промпт-инжиниринг» с прицелом на реальный запуск. Полное ТЗ — `docs/SPEC.md`.

## Текущее состояние
Готов контент: промпты, база знаний, тест-кейсы, конфиги, сборщик документа. **Этапы 1–3 готовы:** ядро (`app/config.py`, `app/prompts.py`, `app/chat.py`), адаптер OpenAI, CLI-чат; `create_handoff` (`app/tools/handoff.py`), SQLite и маскирование ПДн (`app/store.py`), тесты `pytest`; оценка `python -m eval.run` (судья — `eval/judge.md`, отчеты в `build/eval_*.md`). Дальше — этап 4. Инструменты интервью (`get_interview_slots`, `book_interview`) еще не реализованы — пропускаются. Окружение: `.venv` на Python 3.12.

## Источники истины (контент пишет человек)
| Что | Где | Правило для Claude Code |
|---|---|---|
| Системные промпты | `prompts/*.md` | Код только загружает их. Не переписывать без явной просьбы; правки предлагать диффом |
| База знаний | `knowledge/**.md` | То же. YAML front matter: `id`, `assistants`, `status` |
| Тест-кейсы | `tests/cases/*.yaml` | Добавлять кейсы можно, удалять и ослаблять `must` — нет |
| Паспорта ассистентов | `config/assistants.yaml` | Модель, температура, файлы, инструменты |
| Легенда компании | `config/company.example.yaml` | Значения плейсхолдеров `{{КЛЮЧ}}` |

Промпт по каждому ассистенту должен оставаться **самодостаточным и короче 8 000 знаков** после подстановки: тот же текст импортируется в Custom GPTs, Яндекс AI Studio и SMAIPL без кода. Проверка — `python tools/build_docx.py --check`.

## Обезличивание — обязательно
- Реальное название заказчика, его телефоны, адреса, названия яхт-клубов и имена сотрудников **никогда не попадают** в репозиторий, код, тесты, логи и коммиты.
- Бренды верфей (Ferretti, Riva, Sea Ray и другие) — настоящие, их скрывать не нужно.
- Все данные компании — только через плейсхолдеры `{{КЛЮЧ}}`. Значения берутся из `config/company.local.yaml`, если он есть (реальные данные, в `.gitignore`), иначе из `config/company.example.yaml` (легенда).
- Слова-маркеры реального заказчика лежат в `config/forbidden.local.txt` (в `.gitignore`). `build_docx.py --check` ищет их во всех файлах; падение проверки — блокер.

## Целевая архитектура
```
app/
  config.py        # загрузка yaml + .env, подстановка {{КЛЮЧ}}, выбор company.local / example
  prompts.py       # сборка системного промпта: prompts/<id>.md + блок <knowledge> из файлов паспорта
  llm/             # адаптеры провайдеров с единым интерфейсом chat(messages, tools) -> reply
    base.py  openai_compat.py  yandex.py  gigachat.py  anthropic.py
  tools/           # инструменты (function calling)
    handoff.py     # create_handoff: валидация по JSON Schema -> SQLite -> уведомление в чат отдела
    interviews.py  # get_interview_slots / book_interview (MVP: окна из knowledge/hr/vacancies.md)
  store.py         # SQLite: диалоги, карточки; маскирование ПДн в логах
  channels/
    cli.py         # python -m app.channels.cli --assistant sales
    telegram.py    # aiogram 3, отдельный бот на каждого ассистента
eval/
  run.py           # прогон tests/cases/*.yaml + LLM-судья -> отчёт build/eval_<assistant>.md
tools/
  build_docx.py    # рендер плейсхолдеров, проверки, сборка Word-документа
```

Ключевые решения:
1. **База знаний на старте — целиком в контексте** (context stuffing): промпт + база знаний каждого ассистента — около 20 тыс. знаков (менее 10 тыс. токенов), RAG не нужен. Векторный поиск (чанки по заголовкам `###`, урок PEr03) — этап 5, при росте базы.
2. **Карточка передачи работает в двух режимах.** Если модели доступен инструмент `create_handoff`, она вызывает его. Если нет (no-code), выводит текстовый блок «КАРТОЧКА ПЕРЕДАЧИ». Промпты уже написаны под оба режима.
3. **Провайдер переключается через `.env`.** Для реального запуска с ПДн российских клиентов предпочтительны YandexGPT или GigaChat (152-ФЗ, локализация данных).
4. **Без согласия на обработку ПДн контакты не сохраняются:** `pd_consent=false` — блок `contact` отбрасывается на уровне кода, а не только промпта.
5. **Единое окно для посетителя.** На сайте один чат-виджет, а Лоцман, Боцман и Штурман работают за ним. Диалог начинает ассистент по умолчанию (`sales`); при смене темы код переключает активного ассистента (роутер-классификатор и/или инструмент `switch_assistant`), история диалога общая, в шапке виджета — имя текущего ассистента. Промпты остаются самодостаточными. Реализация — `app/router.py` + `app/channels/web.py` (этап 4).

## Стек
Python 3.11+, `openai`, `anthropic`, `gigachat` (SDK), `aiogram>=3`, `pyyaml`, `jsonschema`, `python-dotenv`, `pytest`. Зависимости — в `requirements.txt`, создать на этапе 1.

## Команды
```bash
python tools/build_docx.py --check     # проверки: длина промптов, плейсхолдеры, обезличивание
python tools/build_docx.py             # рендер в build/rendered/ + Word-документ в build/
# появятся по ходу этапов:
python -m app.channels.cli --assistant sales
python -m eval.run --assistant sales
python -m app.channels.telegram --assistant hr
pytest
```

## Этапы (делать по порядку, каждый — отдельный PR или коммит)
1. **Ядро и CLI.** `config.py`, `prompts.py`, адаптер OpenAI-совместимого API, CLI-чат. Критерий: в CLI можно поговорить с каждым из трёх ассистентов.
2. **Карточка передачи.** `create_handoff` с валидацией по схеме, SQLite, уведомление в Telegram-чат отдела (или вывод в консоль, если чат не задан). Критерий: сценарий «запись к менеджеру» создаёт валидную карточку.
3. **Оценка качества.** `eval/run.py`: прогон всех кейсов, LLM-судья проверяет `must` / `must_not`, отчёт в markdown. Критерий: отчёт по трём ассистентам, проходимость ≥ 90 %.
4. **Единое окно и Telegram.** Роутер между ассистентами, веб-виджет (один чат на сайте), Telegram-бот с тем же роутером; история диалога, приветствие из промпта, кнопки из `conversation_starters`. Логи без ПДн.
5. **RAG (по необходимости).** Чанкинг по `###`, эмбеддинги, top-k, метаданные `id` / `assistants`.
6. **Деплой.** Docker, сервер (урок PEn06), мониторинг ошибок.

## Правила работы
- Перед правкой промпта или базы знаний — прогнать `eval` до и после (`--repeat 3`, одиночный прогон слишком шумный) и показать разницу (`python -m eval.compare`).
- Не хардкодить тексты для пользователя в коде: приветствия и формулировки живут в `prompts/`.
- Секреты — только в `.env`. Никаких ключей в коде и тестах.
- В логах и отчётах `eval` телефоны, e-mail и имена маскируются (`+7 9** ***-**-02`).
- Отвечать и комментировать код на русском, идентификаторы — на английском.
